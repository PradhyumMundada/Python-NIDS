# 🛡️ Network Intrusion Detection System (NIDS)

**A Python-Based Network Security Monitoring and Intrusion Detection Prototype**

A rule-based Network Intrusion Detection System (NIDS) built with Python, Scapy, and Flask. The project monitors network traffic, identifies selected suspicious traffic patterns, displays security alerts through a live dashboard, and supports offline analysis of packet captures.

## 📌 Project Overview

Network security monitoring helps identify unusual traffic patterns that may indicate suspicious network activity. This project demonstrates how packet capture, rule-based detection, and a web-based dashboard can be combined into a simple Network Intrusion Detection System.

The system captures network packets, applies predefined detection rules, records alerts, and presents monitoring statistics through a Flask dashboard. It also includes a website security checker for basic technical validation and a separate analyzer for saved Wireshark-compatible packet captures.

> **Note:** This is an educational prototype. Detection results are indicators for investigation, not definitive proof of a cyberattack or a website's maliciousness.

## ✨ Key Features

- **Live Packet Monitoring:** Capture network packets using Scapy.
- **Port-Scan Detection:** Identify traffic patterns that meet the configured port-scan rule.
- **High-Traffic Alerts:** Generate warnings when packet counts cross a predefined threshold.
- **Live Dashboard:** View packet statistics and recorded alerts through a Flask web interface.
- **Automatic Statistics Refresh:** Update dashboard statistics approximately every two seconds without manually reloading the page.
- **Website Security Checker:** Check URL formatting, DNS resolution, connectivity, HTTP responses, and HTTPS certificate validation.
- **Offline PCAP Analysis:** Analyze saved `.pcap` and `.pcapng` files generated by compatible packet-capture tools such as Wireshark.
- **Report Generation:** Export supported website-check results and review packet-analysis summaries and alert records.
- **Windows Launcher Scripts:** Start monitoring and the dashboard using batch files.

## ⚙️ Prerequisites

Before running the project, ensure that you have:

- Windows or another compatible operating system.
- Python installed and available from the terminal.
- Git, if you want to clone or contribute to the repository.
- The Python dependencies listed in `requirements.txt`.
- A network interface you are authorized to monitor.
- Appropriate packet-capture permissions and drivers. On Windows, a compatible capture driver such as Npcap may be required.

## 🚀 Installation and Setup

### 1. Clone the repository

```bash
git clone https://github.com/PradhyumMundada/Python-NIDS.git
```

### 2. Enter the project directory

```bash
cd Python-NIDS
```

### 3. Create a virtual environment (recommended)

```bash
python -m venv .venv
```

Activate it in PowerShell:

```powershell
.\.venv\Scripts\Activate.ps1
```

If activation is blocked by your system's execution policy, use an approved alternative such as running the virtual environment's Python executable directly.

### 4. Install dependencies

```bash
python -m pip install -r requirements.txt
```

## ▶️ Running the Project

### A. Start the dashboard

Open PowerShell in the project directory and run:

```powershell
python dashboard.py
```

Open the local dashboard in your browser:

**http://127.0.0.1:5000**

Keep the dashboard terminal open while using the application.

### B. Start live packet monitoring

Open a **second terminal** in the project directory and run:

```powershell
.\run_nids.bat
```

If necessary, configure the appropriate network interface and capture permissions for your machine.

The monitor processes captured packets and records alerts when its configured rules are triggered. The dashboard displays available statistics and recorded alerts.

### C. Analyze a saved packet capture

Place an authorized `.pcap` or `.pcapng` capture somewhere accessible, then run:

```powershell
python pcap_analyzer.py "C:\path\to\capture.pcapng"
```

Replace the example path with the actual capture-file path.

The analyzer generates its supported alert and summary output files in the project directory. Review these outputs to inspect the analysis results.

### D. Run automated tests

Run:

```powershell
python -m unittest test_detection.py
```

The tests exercise the website-check and detection-related functionality implemented in the test file.

## 📊 Detection Logic

The current prototype uses predefined rules rather than a trained machine-learning model.

### Possible Port Scan

The live detector tracks distinct TCP destination ports for each source IP and generates an alert when the configured threshold is reached.

### High-Traffic Warning

The detector tracks packets within a configured time window and generates a warning when the packet-count threshold is reached.

**Important:** High traffic can result from legitimate activity, and a port-scan indicator can have false positives. Alerts should be interpreted in context and investigated further.

## 🌐 Website Security Checker

The dashboard includes a technical website checker that can examine:

- URL formatting and supported protocols.
- DNS hostname resolution.
- Connection reachability.
- HTTP response status.
- HTTPS certificate validation.
- Report output for the performed check.

A website that cannot be reached is not necessarily malicious. Similarly, a reachable website with a valid certificate is not necessarily safe.

The website checker is not a full malware scanner, phishing detector, or domain-reputation service.

## 🔐 Responsible Use and Privacy

This project is intended for academic learning, authorized network monitoring, and defensive security experimentation.

- Capture traffic only on networks and devices you are authorized to monitor.
- Obtain appropriate permission before analyzing traffic from other users.
- Avoid committing packet captures, alert logs, or statistics that may reveal private information.
- Never commit passwords, API keys, authentication tokens, or other secrets.
- Review generated reports before sharing them publicly.
- Do not treat a detection alert as conclusive evidence of malicious activity.

## ⚠️ Current Limitations

- Detection depends on predefined rules and thresholds.
- False positives and false negatives are possible.
- Encrypted traffic may limit visibility into application-level details.
- Domain identification depends on the information available in captured traffic.
- Offline analysis depends on the contents and quality of the supplied capture.
- Website checks evaluate technical connectivity properties, not comprehensive maliciousness or reputation.
- The prototype does not automatically block network traffic.
